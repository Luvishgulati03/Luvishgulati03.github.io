Henry — a personal AI chief-of-staff

Flagship Open source TypeScript Local-first

Henry started narrow: a force multiplier for my job hunt — track roles, keep the research in one place, stop rewriting the same cover letter. It didn't stay narrow. It became the daily driver that schedules, remembers, drafts, and watches the inbox — a terminal-first agent that runs entirely on an 8 GB M1 Air for roughly zero marginal cost, because it orchestrates CLIs I already pay a subscription for instead of burning metered API keys.

The interesting part isn't that an LLM answers questions. It's the systems around it: a memory engine that decays and reinforces like a real one, a retrieval layer that has to pass an eval harness before any ranking change ships, and an approval boundary that makes autonomy safe to hand out in slices. This site is one of the things Henry tracks.

Five decisions — and what I gave up for each

  1. 01 Local-first memory: files as truth, SQLite as index not chosen → a hosted cloud vector database

    Every memory is a file I can read, diff and git-track; SQLite carries the vector + full-text index beside it. A managed vector DB would have been faster to stand up, but memory about my own life shouldn't live in someone else's tenant, and it shouldn't stop working on a plane.

    CostRetrieval quality became my problem to solve, not a vendor's — which is why the eval harness exists.
  2. 02 Orchestrate subscription CLIs instead of calling metered APIs not chosen → per-token API keys per provider

    Henry dispatches work to multiple provider CLIs with session reuse and intent tiering — light, default and heavy models for different jobs. Marginal cost per run is ~$0, so I could afford to let it run on a schedule and iterate for weeks.

    CostI inherit each CLI's quirks and rate limits, and orchestration code I'd otherwise get from an SDK.
  3. 03 An approval gate on every outbound action not chosen → full autonomy with an undo button

    Nothing leaves the machine — email, GitHub, job applications — without an explicit operator sign-off. The Gmail integration is drafts-only by construction, not by prompt instruction. An agent that can't send is an agent I can leave running.

    CostMore friction, and a real queue to design; "just send it" is a feature I deliberately don't have.
  4. 04 Score-threshold retrieval with per-source caps not chosen → pure top-K

    Top-K always returns K results, even when only two are relevant — weak chunks dilute the answer and one verbose source can eat the whole context. Henry uses a relevance threshold, per-source caps and domain boosts, so a thin question gets a thin, honest context.

    CostThresholds need calibration; a precision@5 / MRR harness now gates every ranking change.
  5. 05 Two stores: decaying personal memory, versioned knowledge not chosen → one unified store for everything

    Personal memory should fade, reinforce and be superseded — what I decided last week outranks what I decided in March. Reference knowledge should do the opposite: stay stable, be versioned, be citable. One store forces one policy; two stores let each obey its own physics.

    CostTwo retrieval paths, two tuning surfaces, and a fusion step that has to decide which store wins.

Three things I got wrong

  • The scheduler that ate the laptop

    A 15-minute cron loop spawned agent subprocesses faster than they finished. On an 8 GB machine that isn't a slow queue — it's a machine you can't type on.

    FixAdmission control: hard caps on concurrent subprocesses, tuned to the RAM I actually have.

  • Distilled cards buried fresh imports

    The strategy-card layer summarised knowledge so well that cards outranked everything, and newly imported sources never surfaced. It looked fine in demos. The eval harness caught it.

    FixScore-interleave instead of cards-first — and no ranking change ships without a P@5 / MRR run.

  • A provider auth failure that looked like success

    An expired provider session returned empty output, and the pipeline happily treated "nothing" as "no results found". Silent wrongness is worse than a crash.

    FixFailure separation everywhere: an engine error can never be reported as an empty result.

Risk AI Council

Pink Unicorn Algorithms · GTM & content lead

Situation

An AI-risk assessment platform with a real engine and no shared language around it. Teams that had to comply with the NIST AI RMF and the EU AI Act weren't ML researchers — they were risk, legal and compliance owners who needed the problem framed in their vocabulary, not ours.

Decisions

  • Wrote for risk & compliance owners, not ML engineers — governance language, not model language.
  • Structured the learning programs as 6 AI-risk categories mapped to NIST AI RMF and the EU AI Act, instead of one undifferentiated course.
  • Rebuilt the site structure to follow the buyer's journey — assess, then learn, then act.

Outcome

6 risk categories shipped as learning programs, framework-aligned end to end.

Learning

In a regulated category, positioning is the product surface. The fastest credibility win wasn't a feature — it was mapping every claim to a named clause a compliance officer already trusts. Vague "responsible AI" copy loses to a citation, every time.

Coding Efficiency Measurement System

0 → 1 · product + full stack

Situation

Coding assessments grade the artefact. Two candidates can submit the same passing solution after wildly different journeys — one reasoned it out, one thrashed and pasted. Institutions were making hiring and grading calls on the half of the signal that's easiest to fake.

Decisions

  • Built a Net Efficiency Score that grades the process: keystrokes, idle time, tab switches, copy/paste, debugging patterns, focus intervals and complexity.
  • Wrote separate PRDs for all three personas — admin, teacher, student — because the same score means three different things to them.
  • Shipped the whole stack myself (Python / Flask / SQLite / JS): role-based workflows, code execution, session recording.

Outcome

Piloted at 2–3 accredited institutions · 3 personas, 3 PRDs, one running platform.

Learning

A process metric is only legitimate if the person being measured can see the same signals the grader sees. The moment the score is a black box it stops being feedback and starts being surveillance — so transparency wasn't a nice-to-have, it was the thing that made the product usable.
