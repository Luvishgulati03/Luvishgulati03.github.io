Coding Efficiency System

Grades the coding process, not the output: keystrokes, idle time, tab switches, debugging patterns. Piloted at 2–3 institutions.

Python · FlaskSQLite3 PRDs

Situation. Assessments grade the artefact. Two candidates submit the same passing solution after wildly different journeys — one reasoned, one thrashed and pasted. Institutions were deciding on the half of the signal that's easiest to fake.

Decisions. A Net Efficiency Score over process telemetry; separate PRDs for admin, teacher and student, because one score means three things; the whole stack shipped solo (Python/Flask/SQLite/JS) with role-based workflows, code execution and session recording.

Learning. A process metric is only legitimate if the person measured sees the same signals the grader sees. Black-box scoring stops being feedback and becomes surveillance.

No public repo — case study on request.

Intent becomes a scheduled job · answers arrive with sources · the send request is refused on purpose.

not chosen → a hosted cloud vector database

Every memory is a file I can read, diff and git-track; SQLite carries the vector + full-text index beside it. A managed vector DB is faster to stand up, but memory about my own life shouldn't live in someone else's tenant — and it shouldn't stop working on a plane.

CostRetrieval quality became my problem, not a vendor's — which is why the eval harness exists.
not chosen → per-token API keys per provider

Henry dispatches work to multiple provider CLIs with session reuse and intent tiering — light, default and heavy models for different jobs. Marginal cost per run is ~$0, so I could afford to let it run on a schedule and iterate for weeks.

CostI inherit each CLI's quirks and rate limits, plus orchestration code an SDK would have given me.
not chosen → full autonomy with an undo button

Nothing leaves the machine — email, GitHub, job applications — without an explicit operator sign-off. The Gmail integration is drafts-only by construction, not by prompt instruction. An agent that can't send is an agent I can leave running.

CostMore friction, and a real approval queue to design. "Just send it" is a feature I deliberately don't have.
not chosen → pure top-K

Top-K always returns K results, even when only two are relevant — weak chunks dilute the answer and one verbose source eats the context. Henry uses a relevance threshold, per-source caps and domain boosts, so a thin question gets a thin, honest context.

CostThresholds need calibration; a precision@5 / MRR harness now gates every ranking change.
not chosen → one unified store for everything

Personal memory should fade, reinforce and be superseded — what I decided last week outranks what I decided in March. Reference knowledge should do the opposite: stay stable, be versioned, be citable. One store forces one policy; two let each obey its own physics.

CostTwo retrieval paths, two tuning surfaces, and a fusion step that has to decide which store wins.

The dashed line is the only interesting part. Everything local — drafts, reminders, memory writes — flows freely. Everything that touches the outside world stops for a human.

The scheduler that ate the laptop

A 15-minute cron loop spawned agent subprocesses faster than they finished. On an 8 GB machine that isn't a slow queue — it's a machine you can't type on.

FixAdmission control: hard caps on concurrent subprocesses, tuned to the RAM I actually have.

Distilled cards buried fresh imports

The strategy-card layer summarised so well that cards outranked everything, and new sources never surfaced. It looked fine in demos. The eval harness caught it.

FixScore-interleave instead of cards-first — and no ranking change ships without a P@5 / MRR run.

An auth failure that looked like success

An expired provider session returned empty output, and the pipeline treated "nothing" as "no results found". Silent wrongness is worse than a crash.

FixFailure separation: an engine error can never be reported as an empty result.
